# Record a decision

This runs after the choice, not before it. Its value is six months out, when
the reasons have faded and only the outcome is visible — and hindsight makes a
good decision with a bad result look like a mistake.

## Write it as

```
## Decision
What was chosen, in one sentence.

## Why
The two to four reasons that actually decided it. Not every
consideration — the ones that carried the weight.

## Assumptions
What has to stay true for this to keep making sense.

## Accepted downside
What the user knowingly took on. Naming it now is what stops
it being a surprise later.

## Next move
The concrete first action, with a date if there is one.

## Revisit if
An observable trigger, not a feeling. "If we haven't signed
two customers by March" rather than "if it isn't working".
```

## Write it in their words

Use what the user actually said. If the reasons came out of a conversation,
take them from there rather than inventing a tidier rationale — a note that
sounds like a consultant wrote it is useless for remembering what was in their
head.

Where a section is genuinely empty, say so briefly rather than filling it. "No
assumptions worth flagging" is a legitimate line. But push gently on two of
them: a decision with no accepted downside usually means one hasn't been looked
at, and "revisit if" with no observable trigger is a wish rather than a plan.

If the decision isn't actually made yet — the user is still weighing it — say
so and stop. That is a different job.

Keep it short enough to reread in a minute. A page nobody opens again records
nothing.
